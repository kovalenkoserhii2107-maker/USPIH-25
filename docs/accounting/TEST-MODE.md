# Отдельная тестовая бухгалтерия

Вход: **Бухгалтерія → Ще → Тестова бухгалтерія**. Также есть ссылка в
настройках. Страница — `accounting-test.html`; доступны голова и бухгалтер.

Тест использует подготовленную обезличенную базу: 302 помещения, 447
записей собственников. Квартира 298 — синтетический пример площадью 64 м².
Учебный период — октябрь–декабрь 2025 года: его можно полностью закрыть,
не подменяя системное время и не начисляя плату за будущие месяцы.

1. «Підготувати тестовий будинок» переносит начальные остатки, историю
   года, поставщика, старый неоплаченный документ и сотрудника. Учебные
   решения согласуются внутри теста; роли рабочей команды не меняются.
2. Выберите месяц и выполняйте шаги: начисления → документ услуги →
   выписка → зарплатные платежи → подтверждение выпиской → закрытие.
   Можно выбрать «Прогнати всі три місяці». Завершённые шаги сохраняются
   на сервере. Повторные вызовы не создают второй комплект операций.
3. Остановка действует между серверными шагами. После закрытия страницы
   можно вернуться с любого устройства под тем же входом и продолжить.
   Если действие продолжается в другой вкладке, нажмите «Оновити стан тесту».
4. Обновите тестовый отчёт правления и выполните сверку. Проверяются
   квартальные и годовые суммы, текущий и депозитный счета, ОСВ, балансы
   квартир, зарплата и связь платежей с проводками.
5. Для ручного разноса добавьте оплату без номера квартиры, затем
   назначьте её помещению. Один и тот же референс с теми же данными не
   дублируется; изменение суммы под использованным референсом запрещено.
   Собственные операции меняют эталонные суммы: сверки фактических
   взаимосвязей остаются, сравнение с неизменным эталоном отключается.
   Оплаты нельзя добавлять в закрытый месяц; для нового сценария очистите тест.
6. Посмотрите баланс и историю тестового жильца. После завершения года
   можно скачать рабочий JSON-архив с пометкой `TEST`.
7. «Очистити лише мій тест» удаляет только данные этого учебного входа.
   Базу можно снова подготовить тем же файлом.

## Изоляция

Реальные бухгалтерские функции выполняются с серверным адаптером базы:
корневые коллекции имеют префикс `sandbox~<Auth UID>~`, вложенные —
`sandbox_`. Группы `ledger` и `owners` рабочей базы не включают тестовые
записи. Запросы тестовых групп дополнительно фильтруются по `_sandboxUid`.
Нативные ссылки другой базы/входа не принимаются в тестовые записи.

Клиентский Firebase SDK не имеет доступа к этим коллекциям. Данные
возвращает только `accountingTestAction` после проверки служебного входа и
финансовой роли; UID берётся из Firebase Auth, а не из запроса страницы.
Параллельные изменения одного теста блокируются серверной арендой операции.
После смены входа страница прекращает следующую операцию и очищает старый вид.

Банковский драйвер создаёт условные референсы и обрабатывает имитированную
выписку. Настоящие токены и исходящие банковские API не используются.
Уведомления отключены. Auth-аккаунты, Storage и реальные квитанции ДПС не
создаются и не меняются. JSON содержит рабочие учебные таблицы, не файл
для государственной подачи и не официальные годовые формы.

Старый публичный запуск `demoAction.run`, который добавлял записи в
рабочую базу, закрыт; интерфейс направляет в отдельный раздел. Уже внесённые
ранее данные автоматически не удаляются. Для очистки рабочей базы есть
отдельный процесс с резервной копией в [IMPORT-AND-RESET.md](IMPORT-AND-RESET.md).
Полная очистка всей базы включает и её тестовые области; кнопка внутри
тестового раздела очищает только текущий тест.

## Проверка и обслуживание

- Ресурс `functions/accounting-test-fixture.json` формируется командой
  `node scripts/package-accounting-test-fixture.mjs` из публичных синтетических
  CSV. Unit-тест сверяет ресурс с исходными файлами и контрольными суммами.
- В эмуляторе выполнены три месяца через существующие функции, повторные
  вызовы, сверки года и публикации, ручной разнос и очистка. Рабочие
  контрольные документы и тест другого UID остались неизменными.
- Через браузер с настоящими серверными действиями на эмуляторе проверены
  ручная оплата, полный цикл, выгрузка архива, перезагрузка и смена входа
  во время подготовки. Ошибок JavaScript нет; на ширинах 320, 390 и
  1280 пикселей нет горизонтального выхода страницы.
- Эталон: текущий счёт **1 829 429,75 грн**, депозит **530 000 грн**,
  долг квартир **48 915,37 грн**, годовые расходы **59 600 грн**,
  доходы **61 100 грн**, результат **1 500 грн**.

При прогоне исправлены две привязки к октябрю 2026: распределение поступлений
в отчёте правления и сверка возвратов теперь используют выбранную дату
начала учёта. Серверные подробности ошибок сохраняются в клиентской
обёртке, поэтому мастер Excel показывает исходный лист и строку.

Проверки не обращались к production и реальному банку. Доступ Firebase Auth
и транспорт HTTPS Callable в локальной браузерной проверке заменены
тестовыми адаптерами; бухгалтерские серверные действия были настоящими.
Индексы для тестовых групп входят в `firestore.indexes.json` и разворачиваются
обычным Deploy Firebase. Кабинет жильца не загружает код тестовой страницы.

`npm run ci`: 280 unit-тестов, проверка проекта и сборка — успешно.
В первом общем прогоне эмулятора прошли 169 из 170 проверок; тест журнала
на 6 011 проводок остановился на тайм-ауте **служебной очистки после проверки**.
Очистка заменена одним управляемым удалением коллекции вместо тысяч
параллельных удалений. Все 11 проверок этого файла повторно прошли, включая
журнал на 6 011 проводок. Дополнительная проверка закрытого публичного запуска
старого демо прошла отдельно. Браузерный цикл с настоящим сервером эмулятора
также завершился без ошибок.

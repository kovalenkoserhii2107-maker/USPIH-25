# Учёт, банк и зарплата: изменения 12.10.2026

## Реализовано

- Настройки даты перехода и формы финансовой отчётности, один основной фонд
  обычных взносов; дополнительные назначения можно добавить позже. Согласует голова.
- Субсчёт и договор депозитного счёта. Размещение и возврат собственного
  депозита не увеличивают доходы или расходы; проценты идут отдельной операцией.
- Сверка входной ОСВ и банковских остатков на конец конкретного месяца.
  Закрытые месяцы сохраняют полный журнал и ОСВ. Поздние изменения источников
  показываются как расхождения, а не меняют сохранённые цифры.
- Перенос истории до выбранной даты. Для перехода в середине месяца —
  подтверждение уже начисленных взносов по всем помещениям, без повторного
  начисления. Общая история проводок проверяется против входной ОСВ.
- Приобретение собственного имущества/запасов отдельно от текущих расходов;
  согласованные бухгалтерские справки для амортизации, потребления запасов,
  аренды, других начислений, переноса между фондами и сторно. Проверяется
  остаточная стоимость, оплата погашает задолженность без второго дохода/расхода.
- Зарплата: проверка всех реквизитов до отправки, восстановление незавершённой
  подготовки без повторения уже отправленных платежей. Для одной физической
  персоны трудовая зарплата и ЦПД учитываются при проверке общей базы ЕСВ.
- Выплата вне приложения связывается с утверждённой ведомостью и банковским
  списанием. Частичная выплата требует точных начисленного дохода, ПДФО и ВЗ;
  произвольная пропорция не подставляется. Поздняя окончательная выплата не
  переписывает начисления закрытого месяца. Старый общий платёж можно связать
  с ведомостью без создания нового платежа.
- ПриватБанк: обычные выплаты по IBAN остаются основным способом. Дополнительно
  доступны группы и получатели зарплатного проекта, связь по РНОКПП/табельному
  номеру, черновик maspay и проверка содержимого после неопределённого ответа.
  Подписание выполняется в Приват24; фактическая выплата подтверждается выпиской.
  Налоги отправляются отдельными платежами по IBAN. Проекты maspay и reqpay
  не смешиваются. Список страниц читается до пустой страницы, POST не повторяется
  автоматически при неопределённом результате.
- Если банк изменил уже импортированную операцию с тем же идентификатором,
  старый разнос сохраняется, появляется расхождение. Голова сверяет изменение
  в открытом периоде; закрытый период не переписывается автоматически.
- Датованные зарплатные ставки: будущий год требует явно заданных параметров;
  утверждённые ведомости сохраняют свои ставки.
- Годовой рабочий комплект: ОСВ, финансовые результаты, баланс по счетам,
  фонды, журнал, контроль полноты, сравнение с предыдущим годом. Скачивание ZIP
  с шестью Excel и JSON. Версии сохраняются неизменными; контрольная сумма
  проверяет целостность повторного скачивания.
- Новые настройки, бухгалтерские справки, зарплатные получатели и архивы
  доступны для чтения голове и бухгалтеру; прямые записи из браузера запрещены.

## Проверка

Итоговый прогон: `npm run ci` — проверка проекта, 266 тестов и сборка
успешны. `npm run test:rules` с Firestore/Storage Emulator — 164 проверки
успешны. Ошибок и пропусков нет. `git diff --check` — без замечаний.

Полные сценарии исполняются на локальных Firestore/Storage Emulator.
Банковский API заменён контролируемыми ответами; переводы и уведомления
реальным людям не выполнялись. Проверяются начисления, платежи и повторные
запуски, частичные выплаты, ЕСВ/4ДФ, проводки, закрытие, перенос истории,
депозит, годовые суммы и сохранение архива.

Интерфейс проверен Chromium на ширинах 320, 390 и 1280 px: настройки,
зарплата, журнал, годовые данные; ошибок JavaScript и горизонтального
переполнения не обнаружено. Скачанный ZIP содержит шесть валидных XLSX
контейнеров и JSON с совпадающими контрольными суммами расчёта.
Эта проверка интерфейса использует локальные адаптеры и не доказывает
доступ к реальному банковскому API.

## Что ещё требуется

- Официальные формы финансовой отчётности и годовой неприбыльный XML:
  нужна проверка актуальных шаблонов, схем и соответствия строк. Рабочий
  комплект не является готовым официальным документом для подписи/подачи.
- Персональная зарплатная база до перехода, особенно уже выданные авансы
  и удержания: перенос общего журнала не заменяет такой регистр или Д1/4ДФ/Д5.
- Старые закрытые месяцы без полного архива не реконструируются автоматически;
  годовой контроль сообщает о недостаточной полноте данных.
- Полный количественный склад и реестр движения основных средств, касса,
  НДС, регулярная аренда и квартирные коммунальные начисления — отдельные
  процессы; справки не заменяют полноценные модули.
- Отмена/переподписание зарплатного пакета, создание получателя в банке,
  отдельный сервис банковских расчётных листов и PDF-квитанций не автоматизированы.
- Проверка с реальным токеном, согласование учётной политики бухгалтером,
  production-развёртывание и восстановление из резервной копии выполняются
  отдельно. Тесты и отправка кода на GitHub не означают развёртывание Functions.

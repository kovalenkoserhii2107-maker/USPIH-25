### A2. Эндпоинты, заголовки, параметры, пагинация

Источник — дословная копия раздела «Взаємодія з API» официального документа в репозитории `Revent24/dino_odoo_erp` (`api_integration/services/privat_api.md`). Она сверена с production-кодом ProzorroUKR (`autoclient_payments`), с TS-клиентом `vplvua/fop-docs-app`, с Go-клиентом `yukal/privatbank-api-go`, с PHP-клиентом `sashalenz/privat24-business-api` и с Python-клиентом `shpigunov/ua_banktools`. Статус: ✅/🟡 — содержимое совпадает во всех пяти независимых реализациях.

**Обязательные заголовки** (цитата: «Усі запити повинні містити обов'язкові поля в header»):
```
User-Agent – клієнтський додаток;
token – отриманий із налаштувань token;
Content-Type – application/json;charset=cp1251.
Підтримувані кодування utf8 і cp1251. Якщо charset не зазначено, кодування за замовчуванням cp1251.
```
- Необязательный заголовок `id` — Client ID для группы предприятий. В ua_banktools он описан так: «`client_id`… remains available for legacy integrations». 🟡
- Prozorro передаёт `{"User-Agent": PB_AUTOCLIENT_NAME, "token": PB_AUTOCLIENT_TOKEN}`. ✅
- **Совет:** всегда ставьте `Content-Type: application/json;charset=utf8` и явный `User-Agent`. Иначе ответ придёт в cp1251, и кириллица в `OSND` и `AUT_CNTR_NAM` сломается при `res.json()` в Node. Если по ошибке пришёл cp1251, декодируйте байты через `new TextDecoder('windows-1251')` (в Node 20/22 с full-icu он поддерживается).

**Все запросы — `GET`** («Запити надсилаються за допомогою методу GET»). Базовый URL — `https://acp.privatbank.ua/api/statements/...`.

| Назначение | URL | Параметры |
|---|---|---|
| Серверные даты, фаза, регламент | `GET /api/statements/settings` | — |
| Остатки за период | `GET /api/statements/balance` | `acc`, `startDate` (обязательно), `endDate`, `followId`, `limit` |
| Транзакции за период | `GET /api/statements/transactions` | то же |
| Промежуточные (с `lastday` по `today`) | `GET /api/statements/balance/interim`, `GET /api/statements/transactions/interim` | `acc`, `followId`, `limit` |
| Последний итоговый день | `GET /api/statements/balance/final`, `GET /api/statements/transactions/final` | `acc`, `followId`, `limit` |

Параметры (дословно):
```
?acc=номер рахунку
&startDate=ДД-ММ-ГГГГ - дата початку (обов'язковий параметр)
&endDate=ДД-ММ-ГГГГ - дата закінчення (необов'язковий параметр)
&followId=id наступної пачки з відповіді (необов'язковий параметр)
&limit=кількість записів у пачці (за замовчуванням 20), максимальне значення - 500, рекомендується використовувати не більше 100
```
«Якщо номер рахунку не зазначено (немає параметра acc= і значення), дані будуть сформовані за всіма активними рахунками.» В `acc` передаётся IBAN, например `UA94305299…`.

**Пагинация.** «Якщо у відповіді параметр exist_next_page: true, значення з next_page_id потрібно підставити в наступний запит у параметр followId для отримання наступної пачки.» Пример: `"next_page_id": "620699370_online"`.
- В одном из примеров (README Onix-Systems) `exist_next_page` приходит строкой `'false'`, а не булевым значением. Сравнивайте так: `String(x) === 'true'`. 🟡
- ua_banktools защищается от зацикливания на повторяющемся `next_page_id` и ставит `max_pages=100`. Делайте так же.

**Фазы и регламент** — ответ `/settings` (дословно):
```json
{ "status": "SUCCESS", "type": "settings",
  "settings": {
    "phase": "WRK",
    "dates_without_oper_day": ["01.01.2018 00:00:00", "..."],
    "today": "30.03.2020 00:00:00",          // дата поточного опер. дня (проміжна виписка)
    "lastday": "29.03.2020 00:00:00",        // дата минулого опер. дня (проміжна виписка)
    "work_balance": "N",                     // N – можна робити запити, Y – запити не робити
    "server_date_time": "30.03.2020 12:03:51",
    "date_final_statement": "28.03.2020 00:00:00" // дата, включно з якої є підсумкова виписка
} }
```
«Якщо значення phase відмінне від WRK, то в цей період запити до API можуть повертатися з помилками.» Перед каждым циклом синхронизации проверяйте `phase === 'WRK' && work_balance === 'N'`. ✅

**Лимиты запросов.** Официальной цифры не нашёл. ❌ Клиент vplvua обрабатывает HTTP 429 с `Retry-After` и делает ретраи с паузами 1, 5 и 30 секунд. Ошибки 401 означают недействительный или просроченный токен. Ответ с ошибкой (ua_banktools `PrivatbankErrorResponse`) содержит поля `status: "ERROR"`, `code`, `serviceCode`. 🟡 Практическая рекомендация: опрашивать не чаще раза в 5–15 минут, `limit=100`.

**Ответ с остатками** (поля дословно): `acc`, `currency`, `balanceIn`, `balanceInEq`, `balanceOut`, `balanceOutEq`, `turnoverDebt`, `turnoverDebtEq`, `turnoverCred`, `turnoverCredEq`, `bgfIBrnm`, `brnm`, `dpd` («дата останнього руху»), `nameACC`, `state`, `atp`, `flmn`, `date_open_acc_reg`, `date_open_acc_sys`, `date_close_acc`, `is_final_bal` (boolean). Суммы приходят **строками** (`"0.00"`). ✅

### A3. Схема транзакции

Пример официального ответа (дословно, с комментариями из документа):
```json
{ "status": "SUCCESS", "type": "transactions", "exist_next_page": true, "next_page_id": "620699370_online",
  "transactions": [{
    "AUT_MY_CRF": "31451288",        // ЄДРПОУ одержувача
    "AUT_MY_MFO": "305299",          // МФО одержувача
    "AUT_MY_ACC": "26184050001514",  // рахунок одержувача
    "AUT_MY_NAM": "Програмiсти та Ko МСБ-ТЕСТ ТОВ",
    "AUT_MY_MFO_NAME": "АТ КБ \"ПРИВАТБАНК\"", "AUT_MY_MFO_CITY": "Київ",
    "AUT_CNTR_CRF": "14360570",      // ЄДРПОУ контрагента
    "AUT_CNTR_MFO": "305299", "AUT_CNTR_ACC": "70214924104032",
    "AUT_CNTR_NAM": "ПРОЦ ВИТР ЗА СТРОК КОШТ СУБ(UAH)",
    "AUT_CNTR_MFO_NAME": "АТ КБ \"ПРИВАТБАНК\"", "AUT_CNTR_MFO_CITY": "Київ",
    "CCY": "UAH",
    "FL_REAL": "r",                  // ознака реальності проведення (r,i)
    "PR_PR": "r",                    // стан p - проводиться, t - сторнована, r - проведена, n - забракована
    "DOC_TYP": "m", "NUM_DOC": "K0108B1WKX",
    "DAT_KL": "07.01.2020",          // клієнтська дата
    "DAT_OD": "07.01.2020",          // дата валютування
    "OSND": "Нарахування вiдсоткiв згiдно депозитного договору N...", // підстава платежу
    "SUM": "0.01", "SUM_E": "0.01",  // сума; сума в нац. валюті
    "REF": "DNCHK0108B1WKX",         // референс проведення
    "REFN": "1",                     // № з/п всередині проведення
    "TIM_P": "02:58",
    "DATE_TIME_DAT_OD_TIM_P": "07.01.2020 02:58:00",
    "ID": "557091731",               // ID транзакції
    "TRANTYPE": "C",                 // тип транзакції дебет/кредит (D, C)
    "DLR": "J63DNDSM0XHY5",          // референс платежу сервісу (payment_pack_ref для платежів через API)
    "TECHNICAL_TRANSACTION_ID": "557091731_online"
  }]}
```
Дополнительные поля по требованиям НБУ (дословно): `UETR`, `ULTMT`, `PAYER_ULTMT_NCEO`, `PAYER_ULTMT_DOCUMENT`, `PAYER_ULTMT_NAME`, `PAYER_ULTMT_COUNTRY_CODE`, `RECIPIENT_ULTMT_NCEO`, `RECIPIENT_ULTMT_DOCUMENT`, `RECIPIENT_ULTMT_NAME`, `RECIPIENT_ULTMT_COUNTRY_CODE`. Для налоговых платежей: `STRUCT_CODE` («код виду сплати»), `STRUCT_TYPE` (КБК), `STRUCT_CATEGORY`. ✅

Как интерпретировать поля:
- **Ключ дедупликации.** Документ говорит дословно: **«Для ідентифікації унікальності платіжних інструкцій використовуйте конкатенацію полів REF+REFN»**. ✅ Поэтому id документа в Firestore: `${REF}_${REFN}` (санитизировать `/`). `ID` и `TECHNICAL_TRANSACTION_ID` храните как вспомогательные. Суффикс `_online` в `TECHNICAL_TRANSACTION_ID` намекает, что значение может отличаться между промежуточной и итоговой выпиской. ❌ не проверено, поэтому как первичный ключ его не используйте.
- **Приход или расход.** `TRANTYPE`: `C` — кредит (поступление на наш счёт), `D` — дебет (списание). ✅ `SUM` всегда положительная строка, знак берите из `TRANTYPE`. Поля `AUT_MY_*` описывают **наш** счёт. В документации они подписаны «одержувача» по примеру входящего платежа. При `D` наш счёт — это плательщик, а `AUT_CNTR_*` — получатель. 🟡 (логически, плюс использование в Prozorro)
- **Окончательность.** Prozorro зачисляет платёж только при условии `transaction["FL_REAL"] == "r" and transaction["PR_PR"] == "r"` и `TRANTYPE == "C"`. vplvua фильтрует так же: `txn.PR_PR === "r" && txn.FL_REAL === "r"`. ✅ Значения `p` (проводиться) и `i` (нереальная или информационная) сохраняйте как «pending» и пересматривайте позже. `t` (сторнирована) и `n` (забракована) — исключать. Окончательную сверку делайте по `/transactions/final` или по периоду до `date_final_statement` включительно. У остатков есть флаг `is_final_bal`.
- **Форматы.** В запросе даты имеют вид `DD-MM-YYYY`. В ответе: `DAT_OD` и `DAT_KL` — `dd.mm.yyyy`, `DATE_TIME_DAT_OD_TIM_P` — `dd.mm.yyyy HH:MM:SS` по киевскому времени (❌ пояс в документе явно не указан), суммы — строки с точкой. Для денег используйте целые копейки: `Math.round(parseFloat(SUM)*100)` или парсинг строки.
- **Кодировка cp1251.** См. A2: по умолчанию ответ приходит в cp1251, нужен `charset=utf8` в `Content-Type`. Клиент dino_odoo держит запасной путь «CP1251 fallback при парсингу відповіді».

### A5. Файлы выписки из Приват24 для бізнесу (запасной вариант импорта)

Официальной спецификации форматов экспорта я не нашёл. ❌ Ниже — реконструкция по стороннему коду (`NadozirnySvyatoslav/l10n_ua`, модуль `l10n_ua_bank_privat`, тесты `test_privat_xls.py`). Статус 🟡/❌: это реконструкция, а не официальный образец.

- **XLS (BIFF8) и XLSX.** Сверху шапка, в первой строке «АТ КБ "ПРИВАТБАНК"». Таблица транзакций — с 3-й строки. Колонки по порядку: `№ документа`, `Дата операції` (ДД.ММ.РРРР), `Час операції`, `Сума` (**со знаком**: «−» списание, «+» поступление), `Валюта`, `Призначення платежу`, `ЄДРПОУ/РНОКПП`, `Назва контрагента`, `Рахунок контрагента`, `МФО контрагента`, `Референс`. Строку с `#ПЕРЕНЕСЕННЯ ЗАЛИШКУ` надо пропускать: это входящий остаток. Автор отмечает, что в XLSX-экспорте может не быть строки с заголовками, поэтому строки транзакций он находит по содержимому (дата в колонке даты).
- **CSV.** Кодировка cp1251, разделитель `;`. Заголовок: `ЄДРПОУ;МФО;Рахунок;Валюта;Номер документу;Дата операції;МФО банку;Назва банку;Рахунок кореспондента;ЄДРПОУ кореспондента;Кореспондент;Сума;Призначення платежу;`. В суммах встречаются оба варианта: `-100 000.00` (пробел-разделитель тысяч) и `750,00` (запятая).
- **MultiCash** (ZIP с `umsatz.txt` и `auszug.txt`, cp1251, `;`). Значимые поля: [1] счёт, [3] дата, [5] назначение, [8] `C`/`D`, [9] № документа, [10] сумма со знаком.
- **DBF** у Приват24 тоже есть, но автор его не поддерживает.
- **1C.** Генерический формат `1CClientBankExchange` (текст cp1251, ключ=значение, секции `СекцияДокумент`). Для Приват24 не проверено. ❌

**Рекомендация.** Делайте импорт, который сам определяет формат: по сигнатуре ZIP, XLS или XLSX, иначе текст. Для текста пробуйте сначала UTF-8 с BOM, потом cp1251. Колонки ищите по нормализованным названиям, а не по позициям. Перед релизом обязательно возьмите у пользователя **реальные** файлы выгрузки и сделайте из них фикстуры тестов. Импорт файла — только запасной вариант: JSON из API надёжнее. Для разбора XLSX в браузере подходит SheetJS (`xlsx`) с cdnjs.

## C. Бесплатная подача отчётности в ДПС из своего ПО с файловым КЕП

### C1. API Електронного кабінету

**Документация.** Официальные страницы известны: https://cabinet.tax.gov.ua/help/api.html, https://cabinet.tax.gov.ua/help/api-registers-int.html (частная часть), https://cabinet.tax.gov.ua/help/api-registers.html (открытые реестры), https://tax.gov.ua/elektronna-zvitnist/opis-api. Ни одну из них я не смог открыть напрямую.

**1) Обмен документами: подача отчётов и получение квитанций.**
- База: `https://cabinet.tax.gov.ua/cabinet/public/api/exchange/`. Подача отчёта: «Метод, що використовується: POST. Додатковий шлях: /report». Данные передаются в JSON, внутри которого лежит **подписанный и зашифрованный** XML в Base64. В документации есть типы `InReportDao` (`contentBase64`, `fname`), `ReturnKvt` (`finalKvt`, `kvtBase64`, `kvtFname`, `numKvt`, `status`; отрицательный `status` означает ошибку) и `RequestKvt`. ✅ (сниппеты официальной страницы)
- Production-код ДП «Прозорро» (`ProzorroUKR/prozorro_tasks/fiscal_bot/tasks.py`) подтверждает этот путь. ✅
  ```python
  requests.post('{}/cabinet/public/api/exchange/report'.format(FISCAL_API_HOST),
                json=[{'contentBase64': request_data, 'fname': filename}], headers=DEFAULT_HEADERS)
  # ответ: data["status"] == "OK", data["id"], data["kvt1Fname"], data["kvt1Base64"]
  # ошибки: status "ERROR_DB" и др.
  requests.post('{}/cabinet/public/api/exchange/kvt_by_id'.format(FISCAL_API_HOST),
                data=<зашифрованный id документа>)
  # ответ: data["status"], data["kvtList"][i] -> finalKvt, kvtFname, kvtBase64
  ```
  - **Заголовка `Authorization` в этом вызове нет.** Аутентификация — это КЕП внутри самого документа плюс шифрование на сертификат ДПС. `request_data` — Base64 от результата внешнего сервиса Prozorro `/encrypt_fiscal/file`, который подписывает и шифрует.
  - Prozorro — юрлицо, так что подача через этот API юрлицом работает на практике. ✅
- Разночтение в формате тела: Prozorro шлёт голый массив `[{contentBase64, fname}]`. Модуль `l10n_ua` (Odoo) шлёт `{"list":[{contentBase64,fname}]}` и при этом добавляет `Authorization` с подписью ЄДРПОУ. ❌ Ориентируйтесь на Prozorro (production) и сверьте с api.html.
- Нужно ли оборачивать CMS-конверт в **транспортный контейнер** (см. C2)? Сниппет api.html говорит, что документ передаётся «у транспортному контейнері». В документации е-кабінету Держфінмоніторингу (cabinet.fiu.gov.ua/help/api.html, тот же движок) прямо требуется подпись ДСТУ 4145 в формате **CAdES-X Long** и шифрование. ❌ Точный байтовый формат проверьте тестовой отправкой.

**2) Частная часть (чтение данных): `https://cabinet.tax.gov.ua/ws/public_api/`.**

### C2. Обмен через «Єдине вікно»: e-mail и SOAP

- **SOAP-шлюз:** `http://soap.tax.gov.ua/WebSrvGate/gate.asmx` ✅ (официальная страница https://tax.gov.ua/elektronna-zvitnist/priymannya-ta-obrobka-elektronnih-dokumentiv-its-edine-vikno; старый адрес — `http://217.76.198.151/WebSrvGate/gate.asmx`). «Квитанції та документи… зберігаються у базах даних сервісу протягом 72 годин». ✅
- Методы (по коду `p2p-sys/OpenPRRO/utils/taxforms.py`, namespace `http://govgate/`, SOAP 1.2) 🟡:
  - `Send(fileName, senderEMail, data)`
  - `ReceiveAll`, `GetMessages`, `GetMessagesEx`, `Receive`, `Delete`
  - для них передаётся подписанный ЄДРПОУ в Base64.
- **E-mail.** Сниппет инструкции ДПС: документы отправляются «на адресу zvit@sta.gov.ua до ІКС "Єдине вікно подання електронної звітності"». 🟡 Адрес `zvit@tax.gov.ua` не подтверждён ни одним источником. ❌ Действует ли e-mail канал в 2026 году, официального подтверждения нет. ❌ Правовая основа — наказ Мінфіну від 06.06.2017 № 557 «Про затвердження Порядку обміну електронними документами з контролюючими органами». ✅
- **Схема** (taxer.ua и Prozorro) 🟡:
  1. XML подписывается КЕП: ДСТУ 4145, CAdES; для новых сертификатов хеш ДСТУ 7564 «Купина».
  2. Подписанный файл шифруется на сертификат шлюза ДПС.
  3. Файл отправляется.
  4. **Квитанция 1** — о получении шлюзом. **Квитанция 2** — о принятии или отклонении.
- **Транспортный контейнер.** Восстановлен по коду `GorulkoAV/EUSignDFS/DFSPackHelper.cs` 🟡:
  - подпись: `"UA1_SIGN\0" + int32LE(len) + CMS`;
  - шифрование: `"TRANSPORTABLE\0" + int32LE(len) + "PRG_TYPE=…\r\nPRG_VER=…\r\nFILENAME=<имя.xml>\r\nEDRPOU=<код>\r\nSTTYPE=1\r\n"`, затем `"CERTCRYPT\0" + int32LE(len) + <сертифікат відправника>`, затем `"UA1_CRYPT\0" + int32LE(len) + <EnvelopedData>`.
  - Нужен ли он в REST API кабинета — см. C1. ❌
- **Имя файла XML.** Подтверждено production-кодом Prozorro (`fiscal_bot/fiscal_api.py`). ✅
  ```
  {C_REG:2}{C_RAJ:2}{TIN:10, дополнен нулями слева}{C_DOC:3}{C_DOC_SUB:3}{C_DOC_VER:2}{C_DOC_STAN:1}{C_DOC_TYPE:2}{C_DOC_CNT:7}{PERIOD_TYPE:1}{PERIOD_MONTH:2}{PERIOD_YEAR:4}{C_STI_ORIG:4}.xml
  ```
  - У Prozorro `authority="2659"` используется и как `C_REG+C_RAJ` (26 и 59), и как `C_STI_ORIG`.
  - `C_DOC_CNT` = `env_number` (1 цифра) + счётчик за месяц (6 цифр).
  - Ваш пример `26590012345678J0100125100000000110120261234.xml` раскладывается так: `26`+`59` | `0012345678` | `J01` `001` `25` | `1` | `00` | `0000001` | `1` | `01` | `2026` | `1234`. Длина 43 символа + `.xml`, что соответствует правилу.
  - Официальный первоисточник правила — «Формат (стандарт) електронного документа звітності» (https://zakon.rada.gov.ua/go/z0243-14). Оттуда подтверждены позиции 1–4 (C_REG, C_RAJ) и 1–8 для XSD (C_DOC, C_DOC_SUB, C_DOC_VER). Остальное — по коду Prozorro.
  - Кодировка XML — `windows-1251`. Prozorro: `<?xml version="1.0" encoding="windows-1251"?>`, корень `<DECLAR xsi:noNamespaceSchemaLocation="J1603102.xsd">`. В `DECLARHEAD` поля: `TIN, C_DOC, C_DOC_SUB, C_DOC_VER, C_DOC_TYPE, C_DOC_CNT, C_REG, C_RAJ, PERIOD_MONTH, PERIOD_TYPE, PERIOD_YEAR, C_STI_ORIG, C_DOC_STAN, LINKED_DOCS, D_FILL (ддммгггг), SOFTWARE`. ✅

### C3. Подпись в браузере

**Библиотека ІІТ «Користувач ЦСК-1. Бібліотека підпису (web)» / EndUser (euscp).**
- Сайт разработчика: http://js.sign.eu.iit.com.ua/, загрузки — https://iit.com.ua/downloads (`EUSignJavaScriptD.doc` с описанием API). ✅ (существование, сниппеты) В апреле 2026 вышло обновление web-библиотеки под ДСТУ 7564 «Купина» (inforesurs.gov.ua). ✅ Описание с той же страницы: «можна підписувати дані з форми… або файли», выбирается ключ «Key-6.dat» с паролем. ✅
- Схема «как в кабинете ДПС» (README `l10n_ua_sign`) 🟡: «бібліотека працює у web worker браузера, приватний ключ і пароль не залишають клієнт, сервер отримує лише готові підписи». Ключи бывают `.dat`, `.jks` и `.pfx`.
- Нужны файлы:
  - `euscp.js` — класс `EndUser`;
  - `euscp.worker.js` — около 17 МБ, вся криптография;
  - `data/CAs.json`;
  - `data/CACertificates.p7b`.
- Источники файлов:
  - npm `@it-enterprise/digital-signature` (последняя версия 1.5.3 от 02.10.2026, обёртка под ISC). Там лежат `euscp/euscp.js` и `dist/euscp.worker.js`, CDN: `https://cdn.jsdelivr.net/npm/@it-enterprise/digital-signature@<ver>/...`;
  - `CAs.json` и `CACertificates.p7b` — **из кабинета ДПС**: `https://cabinet.tax.gov.ua/ws/api/crypto/public_sign/data/CAs.json`, `.../CACertificates.p7b`. По опыту автора l10n_ua, `.p7b` с сайта IIT (сборка сентября 2026) роняет `Initialize` с кодом 49.
- API (из `euscp.d.ts`): `Initialize({CAs, CACertificates, httpProxyServiceURL, directAccess, …})`, `ReadPrivateKeyBinary(keyBytes, password, null, caName)`, `SignDataInternal(appendCert, data, asBase64)` (CAdES с данными внутри), `EnvelopData(recipientsCerts, data, signData, appendCert, asBase64)`, `ASiCSignData`, `ResetPrivateKey()`.
- **CORS к ЦСК.** Читая ключ, библиотека обращается к ЦСК (OCSP/CMP). Для ЦСК с `"directAccess": true` (КНЕДП ДПС, «Дія») это работает прямо из браузера. Для остальных нужен свой **HTTP-прокси** (`httpProxyServiceURL`), пропускающий только хосты из `CAs.json`. Это легко сделать HTTPS-функцией Cloud Functions.
- **Лицензия.** Библиотека IIT проприетарная. ❌ Условия бесплатного использования на стороннем сайте не нашёл. Совет l10n_ua: «перед розповсюдженням файлів звірте умови IIT». Сам КЕП ДПС бесплатен. Запросите у IIT письменное подтверждение или подгружайте файлы с CDN, а не из вашего публичного репозитория.
- **Форматы для ДПС.** Отчётность: CAdES, внутренняя подпись (данные внутри) с сертификатом. В документации е-кабінету ФМ указан CAdES-X Long. Шифрование — EnvelopedData на сертификат ДПС. XAdES и ASiC для отчётов в ДПС не требуются. 🟡 Алгоритм хеша: `/ws/api/crypto/public_sign/hashAlgo` отдаёт `DSTU7564`, и с 01.09.2026 новые сертификаты выпускаются с ДСТУ 7564. Проверьте, что в сборке worker есть `EU_CTX_HASH_ALGO_DSTU7564_256`. 🟡
- **Открытая альтернатива:** `dstucrypt/jkurwa` (ДСТУ 4145 на чистом JS, есть разбор транспортных заголовков `UA1_SIGN`/`UA1_CRYPT`). Это неофициальная библиотека, её совместимость с новыми ключами и форматом Key-6 ❌ не проверена.

**Віджет підпису id.gov.ua.**
- Встраивается через iframe и скрипт `eusign.js` (npm `eusign`, «Module for interaction with iframe SignWidget»).
- URI с версией: `https://id.gov.ua/sign-widget/v20200922`, `.../v20220527/` (встречаются в коде).
- Пример вызова: `new EndUser(parentId, 'sign-widget', 'https://id.gov.ua/sign-widget/v20200922', EndUser.FormType.SignFile)` → `.ReadPrivateKey()` → `.SignData(bytes, false, true, EndUser.SignAlgo.DSTU4145WithGOST34311, null, EndUser.SignType.CAdES_X_Long)`. 🟡 (код `YBashtovyi/3S-framework`, документация EPAM DDM)
- Плюсы: файловые ключи, токены, Дія.Підпис и облачные ключи без хостинга 17 МБ библиотеки. Ключ читается внутри iframe на origin id.gov.ua.
- Минусы и неизвестное:
  - есть ли в виджете `EnvelopData` (шифрование на сертификат ДПС) — ❌ не проверено; без него подачу в ДПС полностью не собрать;
  - условия бесплатного встраивания на сторонний сайт — ❌ не нашёл (для **авторизации** через id.gov.ua нужен договор с оператором, для виджета подписи — неизвестно).
- Вывод: виджет хорош для простых подписей документов ОСББ (протоколы, акты). Для отчётов в ДПС надёжнее EndUser от IIT, у которого есть `EnvelopData`.

## D. Рекомендации

### Что реально сделать бесплатно

1. **Банковская выписка из ПриватБанка через Автоклієнт.** Бесплатно, без лицензий, работает стабильно ✅. **Рекомендую как основной канал.** Импорт файла держать как запасной.
2. **QR-код и ссылка НБУ.** Полностью клиентская генерация, бесплатно ✅. Формат 003, ссылка `https://qr.bank.gov.ua/…`, поле 10 непустое, знак ₴ в центре. Это даёт однозначное назначение платежа и `reference` для автосверки.
3. **Подготовка отчётов.** Генерацию XML по XSD (J0101911, J0500111, фінзвітність) и XSD-валидацию делать в приложении — бесплатно ✅.
4. **Подача в ДПС прямо из приложения.** Технически возможна: REST `exchange/report` подтверждён production-кодом Prozorro, библиотека IIT EndUser работает в браузере. Но остаются три неясности:
   - лицензия IIT ❌;
   - точный формат контейнера и тела ❌;
   - CORS кабинета для браузера ❌.

   **Практичный вариант для MVP:**
   - приложение генерирует валидный XML с правильным именем файла;
   - пользователь сам загружает его в https://cabinet.tax.gov.ua («Звітність → Завантажити»), где кабинет подписывает файл тем же КЕП, бесплатно.

   Прямую подачу делать вторым этапом, после тестовой отправки.

### Безопасная архитектура (Firebase)

**Банк**
- Токен Автоклієнта хранится **только на сервере**: Secret Manager через `defineSecret('PB_AUTOCLIENT_TOKEN')` в Cloud Functions v2 или документ Firestore с правилами `allow read, write: if false`. В браузер, localStorage и логи он не попадает.
- Пользователь вводит токен один раз в форме. Callable-функция принимает его, проверяет вызовом `/settings` и сохраняет. Ответ — только «подключено / не подключено».
- Синхронизация — `onSchedule` в `europe-central2`:
  - раз в 10–15 минут в рабочие часы и раз в сутки ночью;
  - сначала `GET /settings`; если `phase !== 'WRK'` или `work_balance === 'Y'`, пропустить цикл;
  - затем `transactions/interim`, а раз в сутки `transactions?startDate=<date_final_statement−N>&endDate=…` для финализации;
  - `limit=100`, цикл по `followId` с защитой от повторов, экспоненциальный backoff на 429 и 5xx.
- Запись в Firestore: `banks/{acc}/tx/{REF}_{REFN}` через `set(..., {merge:true})`. Сохранять сырой JSON, статус `final = (PR_PR==='r' && FL_REAL==='r')`, сумму в копейках, знак из `TRANTYPE`, курсор синхронизации. Сопоставление с квартирами — по `reference` из QR, ЄДРПОУ/РНОКПП плательщика и номеру квартиры в `OSND`.
- Ограничение по IP в Автоклієнте: у Cloud Functions нет постоянного исходящего IP. Статический IP требует VPC connector и Cloud NAT, а это платно. Поэтому поле IP-ограничения оставить пустым или осознанно платить за NAT.
- Firebase: исходящие запросы к внешним API и scheduled-функции работают только на тарифе **Blaze** (pay-as-you-go). В бесплатную квоту такая нагрузка укладывается. ❌ Лимиты тарифа здесь не перепроверял.

**ДПС / КЕП**
- **Ключ и пароль никогда не покидают браузер.** Подпись и шифрование выполняет EndUser IIT в web worker. Сервер (Cloud Function) получает только готовый Base64-конверт и имя файла и просто пересылает их в `cabinet.tax.gov.ua/cabinet/public/api/exchange/report`. Это нужно, если кабинет не отдаёт CORS-заголовки.
- Ещё одна функция — прокси к ЦСК со строгим allowlist хостов из `CAs.json`, без логирования тел запросов.
- Сертификаты ДПС (`EK_C_NEW.cer`) и `CAs.json`/`CACertificates.p7b` загружать с кабинета при каждом использовании (`cache: 'no-cache'`), не зашивать в код.
- Квитанции: `kvt_by_id` или `/ws/public_api/post/incoming` (с подписанным в браузере `Authorization`), расшифровка — в браузере тем же ключом.

**Content-Security-Policy на GitHub Pages:** разрешить `worker-src 'self' blob:` и домены CDN, с которых грузится euscp.

### Что проверить до реализации (❌)

1. В Приват24 для бізнесу: можно ли при создании Автоклієнта ограничить права только выписками и балансами, и сколько живёт токен.
2. Открыть https://cabinet.tax.gov.ua/help/api.html браузером и сверить:
   - тело `/report` (массив или `{list:[...]}`);
   - нужен ли транспортный контейнер `TRANSPORTABLE`/`UA1_SIGN`/`UA1_CRYPT`;
   - нужен ли `Authorization`;
   - есть ли CORS.
3. Условия лицензии IIT на web-библиотеку для некоммерческого или стороннего сайта.
4. Реальные файлы выгрузки выписки (XLS, CSV) у пользователя — для фикстур.
5. Актуальный реестр форм: J0901205 или S0111007 для микро-ОСББ на 2026 год; переход J0500110 → J0500111.
6. Сканирование QR 003 в приложении Ощадбанка.

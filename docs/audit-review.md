# Разбор аудита USPIH-25: что делать, что менять и чего не делать

## 0. Вывод в двух абзацах

**Факты в аудите в основном верны.** Я проверил по коду все 28 разделов: примерно 22 подтверждаются полностью, 4 — частично или с завышенной важностью, 2–3 спорные или почти наверняка ложные (лимит 500 записей в batch, сдвиг дат XLSX, `Date()` без `new`). Ошибку `toKop` я воспроизвёл: `"100.0000"` превращается в **1 000 000,00 грн**.

**Слабость аудита в другом: это список симптомов без корневых причин, и важность расставлена неточно.** Почти все 30 ошибок вырастают из 6–7 архитектурных решений (раздел 2). Если чинить их по одной, через месяц появятся новые такие же. Предложенный «Приоритет 1 — один быстрый PR» с проверкой домена `@uspih-25.com` **не закрывает главную дыру**. Он создаёт ложное чувство безопасности: злоумышленник просто зарегистрирует `<свободный номер>@uspih-25.com` (подробно в пункте 1).

## 2. Корневые причины (то, чего нет в аудите)

| # | Корневая причина | Какие пункты аудита из неё растут |
|---|---|---|
| **R1** | **Модель идентичности.** Логин — `<номер>@uspih-25.com`, роль берётся из префикса email → `staff/{номер}`. Custom claims нет, регистрация в Firebase Auth, скорее всего, открыта (ключ публичный, учётки заводятся «как для квартир»). Каждое правило держится на `myApt()` = `email.split('@')[0]`. | 1, 2, частично 24, 27 |
| **R2** | **Мульти-ОСББ сделано префиксами путей в той же базе Firestore.** Основной дом лежит в корне, чужие — в `sandbox~tenant_<slug>~*` через Proxy-адаптер. Правила Firestore к тенантам не применяются, Auth о тенантах не знает, а «супер-админ платформы» — это просто голова «Успіх-25» (и его бухгалтер). | 4, 7, 8, 9, 10 — весь кластер PR #102 |
| **R3** | **Тестовые двойники в боевом коде.** «Песочный» токен Приват24 распознаётся регуляркой прямо в `privat.js`. Симулятор банка можно направить на основной дом (`bankSetupSimulator` при отсутствии боевого токена). Старый `demoAction` с разрушительным `sweep` до сих пор задеплоен. Есть клиентский fallback для платформы. | 5, 7, 9.2, 10, 20, 21 |
| **R4** | **Бизнес-номера используются как ID документов, а запись идёт через `set(..., {merge:true})` вместо create/update.** `safeId` вырезает кириллицу (`\w` без флага `u`), поэтому «АЗ-1» и «АО-1» → `_-1`. Upsert молча перезаписывает или создаёт документы-призраки. | 3 (призраки), 6.2, 6.3, 12 |

| **R6** | **Логика дублируется.** Три разных `toKop`: серверный на BigInt правильный, два клиентских — нет. Ядра ESM/CJS скопированы между `js/` и `functions/`. `DemoDate` вставлен в каждый HTML. `safeFileUrl`/`isOwnFileUrl` применяются не везде. | 6.1, 11.3, 14 |
| **R7** | **Гигиена.** Часть исходников лежит минифицированной: `database-reset.js` — 18 КБ в 95 строках, так же `migration.js`, `accounting-test.js`. Как раз самый разрушительный код невозможно отревьюить. SDK Firebase: в браузере 10.14.1 с gstatic, в devDeps — 12.19.0. Нет App Check, нет регулярного бэкапа (PITR/экспорт): копия делается только внутри процедуры сброса. | усиливает всё остальное |

**Сильные стороны — их нельзя потерять при исправлениях.** Деньги на сервере считаются в целых копейках через BigInt. Чистые `*-core.js` покрыты тестами. Закрытие периодов (`period-lock`) работает, журнал аудита ведётся, тесты правил гоняются в CI. Денежные операции идут только через Cloud Functions, перед сбросом базы делается резервная копия.

## 4. Найдено дополнительно (в аудите нет)

1. **Симулятор банка может писать в основной дом** (см. п. 7) — High.
2. **Нет разделения обязанностей:** голова сам составляет, утверждает и подписывает. Для маленького ОСББ это допустимо, но тогда нужен хотя бы явный след в журнале и отдельное действие «утвердить».
3. **Минифицированный исходник критичного кода:** `database-reset.js`, `migration.js`, `accounting-test.js`, части `claims-core.js`, `buh-migration.js`. Прогнать через Prettier — нулевой риск и большой выигрыш для ревью.
4. **`apartments.balance` хранится во float-гривнах** (`balance: a.balanceKop/100` в миграции), хотя принцип проекта — целые копейки. Источником должен быть `balanceKop`, `balance` — только производное для отображения.
5. **Нет регулярного бэкапа** (PITR и ежедневный экспорт Firestore → GCS) и **нет App Check** на callable-функциях.
6. **Нет CSP.** На GitHub Pages можно задать её через `<meta>`; без `'unsafe-inline'` она закрывает весь класс `javascript:`-XSS (inline-скрипты с `DemoDate` перевести на hash).
7. **Расхождение версий Firebase SDK** (10.14.1 в браузере против 12.19.0 в devDeps); CDN без SRI.
8. **Ядра ESM/CJS скопированы вручную** (`advance-core`, `claims-core`, `platform-core` отличаются только `export`). Генерировать CJS из ESM тем же esbuild, который уже есть в проекте.

## 5. Чего лучше НЕ делать

1. **Не выпускать «один быстрый PR с проверкой домена» как решение пункта 1.** Без отключения sign-up и без custom claims он ничего не закрывает, а все решат, что проблема решена.
2. **Не чинить кластер PR #102 (пункты 4, 7–10) по одному.** Сначала решить модель тенантности (R2). До этого спрятать платформу за флагом, оставить её только `chair` и запретить симулятору писать в основной дом. Варианты на выбор: отдельный Firebase-проект на каждое ОСББ (проще и надёжнее всего для 5–50 домов), named databases, или `tenantId` в claims + правила.
3. **Не латать `demoAction.sweep`** — удалить эндпоинт целиком.
4. **Не переписывать batch-и «под 500» и не трогать `toDate` по аудиту без теста.** Первое, скорее всего, не нужно, второе может сломать правильное поведение.
5. **Не включать `autoApply` для внешних реестров** (YouScore, ДРРП) — только предложение и подтверждение человеком.
6. **Не начинать сейчас переписывание на TypeScript или фреймворк.** Риск большой, выгода сейчас маленькая. Достаточно `// @ts-check` + JSDoc в денежных `*-core.js` и ESLint с несколькими правилами.
7. **Не добавлять новые функции** (платформа, мультибанк, новые формы ДПС) до закрытия этапов 0–2. Объявить feature freeze на 2–3 недели.
8. **Не держать симулятор и тестовые токены в боевом проекте.** Нужен отдельный `uspih-25-staging`, и `isSandboxToken` уходит из боевого `privat.js`.
9. **Не тратить время на демо-мелочи** (`DemoDate`, `Filter.or`, blob) раньше безопасности и денег.

# ОСББ «Успіх-25» — вебзастосунок мешканця

Статичний застосунок на ванільному JavaScript (ES-модулі, без бандлера).
Хостинг: GitHub Pages. Бекенд: Firebase (Auth + Firestore + Storage).

## Структура

```
index.html          розмітка всіх екранів
style.css           єдина дизайн-система (усі кольори — у :root)
firestore.rules     правила доступу — ОБОВ'ЯЗКОВО опублікувати
js/
  firebase.js       ініціалізація Firebase + об'єкт сесії
  ui.js             утиліти: екранування, формати, панелі, сповіщення
  attachments.js    типи файлів, галерея, переглядач документів
  owners.js         співвласники (атомарне збереження)
  power.js          статус електропостачання
  messages.js       розсилка та вхідні оголошення
  requests.js       звернення мешканців + база документів ОСББ
  app.js            точка входу: вхід, маршрутизація, навігація
```

---

## ⚠️ ЩО ТРЕБА ЗРОБИТИ ПІСЛЯ ЗАЛИВКИ

Без цих трьох кроків застосунок працюватиме неправильно.

### 1. Опублікувати правила доступу

Firebase Console → **Firestore Database → Rules** → вставити вміст
`firestore.rules` → **Publish**.

Це головний захист. Раніше номер квартири брався з тексту на екрані,
тому будь-хто міг підмінити його через DevTools і писати в чужу квартиру.
Тепер код бере квартиру з токена автентифікації, а правила це підтверджують
на сервері.

### 2. Створити два складені індекси

Нові запити фільтрують дані **на сервері**, а не в браузері. Firestore
вимагає для них індекси. Найпростіший спосіб: увійти в застосунок,
відкрити консоль браузера (F12) — Firebase сам надрукує помилку
`FAILED_PRECONDITION` з готовим посиланням «Create index». Натиснути його
двічі (для двох запитів) і зачекати 1–2 хвилини.

Або створити вручну в **Firestore → Indexes → Composite**:

| Колекція   | Поля                                             |
|------------|--------------------------------------------------|
| `messages` | `recipients` (Arrays) + `createdAt` (Descending) |
| `requests` | `apt` (Ascending) + `createdAt` (Descending)     |

### 3. Перевірити міграцію старих повідомлень

Повідомлення тепер мають поле `recipients` — саме воно дозволяє
фільтрувати на сервері. Старі оголошення його не мають, тому при
**першому вході адміна** запускається тиха міграція, яка дозаповнює
це поле. Просто увійдіть один раз як адмін і перевірте, що старі
оголошення видно мешканцям.

## Локальний запуск

ES-модулі не працюють через `file://`. Потрібен будь-який статичний сервер:

```bash
python3 -m http.server 8000
```

Далі відкрити `http://localhost:8000`.

## Оновлення кешу

У `index.html` посилання на файли мають параметр версії
(`style.css?v=1`, `js/app.js?v=1`). Після зміни коду збільште число,
щоб браузери мешканців підхопили нову версію.

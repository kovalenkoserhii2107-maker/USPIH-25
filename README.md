# ОСББ «Успіх-25» — вебзастосунок мешканця

Статичний застосунок на ванільному JavaScript (ES-модулі, без бандлера).
Хостинг: GitHub Pages. Бекенд: Firebase (Auth + Firestore + Storage).

## Структура

```
index.html          розмітка всіх екранів
style.css           єдина дизайн-система (усі кольори — у :root)
style-chat.css      стилі чату
firestore.rules     правила доступу до Firestore
storage.rules       правила доступу до файлів
firestore.indexes.json індекси Firestore
functions/          захищені серверні операції та синхронізація ДТЕК
js/
  firebase.js       ініціалізація Firebase + об'єкт сесії
  ui.js             утиліти: екранування, формати, панелі, сповіщення
  attachments.js    типи файлів, галерея, переглядач документів
  owners.js         співвласники (атомарне збереження)
  power.js          статус електропостачання
  messages.js       розсилка та вхідні оголошення
  requests.js       звернення мешканців + база документів ОСББ
  polls.js          опитування (створення, голосування, підсумки)
  meetings.js       вкладка «Збори»: створення, активні, архів, протоколи
  meeting.js        розрахунки зборів: кворум, підсумки питань (без DOM)
  paper_votes.js    внесення голосів, зібраних на папері під час обходу
  protocol_pdf.js   листки письмового опитування і протокол зборів (pdfmake)
  protocol_form.js  дані, які дописуються в протокол перед формуванням
  app.js            точка входу: вхід, маршрутизація, навігація
```

## Загальні збори співвласників

Збори — це запис у колекції `polls` з `isMeeting: true`. У полі `options`
лежить не список варіантів відповіді, а **порядок денний**; першим питанням
код завжди додає «Обрання голови та секретаря зборів». Відповіді на кожне
питання фіксовані: «За», «Проти», «Утримався».

Голос квартири — документ `polls/{id}/votes/{apt}`:

```
{ answers: { "0": "За", "1": "Проти" },   // ключ — номер питання
  source: "paper",                        // лише для голосів з обходу квартир
  enteredBy: "12",                        // хто вніс паперовий голос
  votedAt: ... }
```

Збори живуть у власній вкладці правління — «Збори»: форма створення,
активні збори, архів (і те, і те можна редагувати) та список протоколів.
Опитування лишилися на своїй вкладці й про збори нічого не знають.

Перше питання порядку денного однакове на всіх зборах, тому в формі
стоять не його формулювання, а поля «голова» й «секретар» (з підказкою
зі списку співвласників): рішення та «Слухали» для протоколу складаються
самі. Решта питань нумерується формою — номер вписувати не треба.

До кожного питання правління пише проєкт рішення (`agendaDecisions`) —
він друкується на листку опитування під питанням і потім лягає в протокол
рядком «Вирішили». Перед формуванням протоколу відкривається вікно, де
дописуються номер протоколу, голова й секретар зборів та «Слухали»
(`protocolNumber`, `chairName`, `secretaryName`, `agendaHeard`).

Голосування відкривається в час початку зборів (`votingOpensAt` — його
перевіряють і застосунок, і правила Firestore). До того мешканець бачить
порядок денний із проєктами рішень, але кнопки голосування ще немає:
голос до обговорення — це голос наосліп. Паперовий обхід правління може
вести й раніше — на нього обмеження не поширюється.

Листки опитування друкуються окремим комплектом на КОЖНЕ питання і,
якщо ввімкнено `sheetsByEntrance`, окремо на кожну парадну — саме так їх
роздають відповідальним особам. Внесення зібраних голосів іде тим самим
розрізом: спершу питання, потім парадна, далі суцільний список квартир,
де треба лише позначити «За», «Проти» чи «Утримався». Відповіді
записуються злиттям, тож голос за друге питання не стирає перший.
На кожній сторінці листка стоїть ПІБ особи, яка проводить опитування,
і місце для її підпису — відповідальних задають у формі зборів
(`surveyors`), для кожної парадної свого.

Завершивши збори, правління кнопкою «Сформувати протокол» отримує
готовий PDF. Протокол лягає в Базу документів ОСББ (категорія
«Протоколи зборів») і йде розсилкою всьому будинку.

**Що попереду.** Голосує квартира: голос — це документ із номером
квартири замість ідентифікатора. Коли зʼявиться електронний підпис,
голосувати зможе лише співвласник, який пройшов процедуру підпису, —
модель голосу доведеться розширити з квартири на конкретну особу.

**Як рахуються голоси.** За Статутом ОСББ кожний співвласник має один
голос незалежно від площі своїх приміщень, а рішення ухвалюється
більшістю від ЗАГАЛЬНОЇ кількості співвласників будинку, а не від тих,
хто взяв участь. Виняток — перше питання про обрання голови та секретаря:
його вирішує більшість присутніх, інакше збори не було б кому вести.
Площа в документах теж є: вона стоїть поруч із голосами в кожному рядку.

Обидва документи повторюють ті, що ОСББ веде на папері, — структура,
шапки таблиць і формулювання збігаються з чинними зразками.

`pdfmake` вантажиться з CDN у мить першого натискання, а не в `<head>`:
разом зі шрифтами це близько двох мегабайтів, і мешканцям, які ніколи
не формують протоколів, вони не потрібні. Якщо cdnjs недоступний,
береться запасне джерело (jsDelivr).

## Розгортання Firebase

Правила Firestore і Storage, індекси та Cloud Functions описані в репозиторії
й розгортаються однією командою:

```bash
npm ci --prefix functions
firebase deploy --only firestore:rules,firestore:indexes,storage,functions
```

Завершення зборів і публікація протоколу виконуються на сервері через
ідемпотентні функції: повторний запит не створює дублікати документів або
оголошень.

### Одноразове налаштування Authentication

**Authentication → Settings**:

- **Password policy** — мінімум 8 символів, режим *Require enforcement*.
  Старі паролі продовжать працювати, нові короткі — ні.
- **User account management → Email enumeration protection** — увімкнути,
  щоб за відповіддю на вхід не можна було перебрати, які квартири
  зареєстровані.

Ці параметри задаються в консолі Firebase і не входять до статичних файлів
проєкту.

## Локальний запуск

ES-модулі не працюють через `file://`. Потрібен будь-який статичний сервер:

```bash
npm ci
python3 -m http.server 8000
```

Далі відкрити `http://localhost:8000`.

## Перевірки

```bash
npm run ci
npm test --prefix functions
```

Інтеграційні тести правил потребують Java 21 і Firebase Emulator Suite:

```bash
firebase emulators:exec --project uspih-25-rules-test --only firestore,storage "npm run test:rules"
```

## Оновлення кешу

У `index.html` посилання на файли мають параметр версії
(`style.css?v=107`, `style-chat.css?v=107`, `js/app.js?v=107`). Після зміни
коду збільште число разом із `VERSION` у `sw.js`. Команда `npm run check`
перевіряє узгодженість версій, імпортів та Firebase-конфігурації.
